## Residuals (recorded, not fixed)

- **Focus after an in-page view swap (corrected by the second pass).** On the join screen the "Lost your browser? Recover your seat" and "Back to join by code" buttons do *not* unmount: both modes render a `<main>` with a `secondary-action` at the same child position, so React reuses the DOM node, focus stays on it, and its accessible name changes in place (probed in jsdom by the reviewer). The first draft of this record wrongly said focus fell to `<body>`. What remains is (a) a control whose name and purpose change under focus, softened by the new `<h1>` and the surrounding text, and (b) the recovery **success** card: the submit button's form unmounts, so focus is lost (inferred, not probed), and the display-once replacement code sits outside a live region (the polite region says only "Seat recovered."). Both match the existing create/join reveal cards, which passed three review rounds, and there is no route- or view-level focus management anywhere in the app, so this is a design decision rather than a narrow fix. Not shown to be a WCAG 2.4.3 failure; browser behaviour after a removed focused node varies, so how a keyboard user resumes is unverified. Suggested follow-up if John wants it: move focus to the new view's `<h1>` (`tabIndex={-1}`) on mode change and on the reveal card, and include the new code in the announcement's target region.
- **`page-has-heading-one`** on the intentional nonexistent-room route (F7 remainder), unchanged and non-WCAG.
- **320 px with 200% text-only scaling** remains recorded, not gating (documented in the reskin review).
- The correction sheet's mount-time inert snapshot, and the one-dialog assumption, remain accepted.
- The modal audit opens the first roster row's sheet (Iryna); sheet height varies with the character, so the tallest sheet (most items and abilities) is not specifically targeted. The sheet's body scrolls internally, and the scenarios that gate (reachable last field, footer cap, 150%/200% text) pass for that row.

## Limits of this evidence (state plainly)

- **Headless Chrome, not iOS Safari.** iOS Safari's on-screen keyboard shrinks only the *visual* viewport while the layout viewport stays put; headless Chrome cannot produce that (`Emulation.setVisibleSizeOverride` no longer exists), and the audit's "keyboard" case shrinks the layout viewport, which is the Chrome-Android `resizes-content` behaviour. The `useVisualViewportBox` hook that handles the iOS case is covered in jsdom and its use of `--vv-*` by the pinch-zoom scenarios in a real engine, but it has **never run on a physical iPhone**. The recovery form is an ordinary in-flow page (not a pop-out); how iOS scrolls its fields above the keyboard is unverified. Whether iOS honours `autocapitalize="characters"` on this input, and whether its autocorrect really is suppressed, is likewise a device fact this pass did not observe; the server-side-safe client normalisation exists precisely so the result does not depend on it.
- **No screen reader.** VoiceOver (iOS/macOS), TalkBack and NVDA were not run. Everything about accessible names, descriptions (`aria-describedby` on the new button), live-region announcements and focus order rests on axe-core (0 hard violations across 162 states), jest-axe, and reading the accessibility tree via testing-library roles. `docs/ARCHITECTURE.md` section 13/16 still lists the VoiceOver/iOS and NVDA/Windows manual flows as owed before public preview.
- **No physical device.** Touch is emulated (`Emulation.setTouchEmulationEnabled`); real thumb reach, dynamic browser chrome (the collapsing URL bar), the iOS home-indicator/notch in a real Safari, and momentum scrolling are unmeasured. Safe-area insets are emulated values.
- One Chrome on one machine; no Safari, Firefox, Android browser or Windows High Contrast run.
- The injury-choice step (the Cowboy hat button) was measured from a static render at ~500 px, not in the live flow at phone width.
- Staging Hosting still serves the pre-fix build: none of this is visible on the deployed URL until an explicitly authorized redeploy.
